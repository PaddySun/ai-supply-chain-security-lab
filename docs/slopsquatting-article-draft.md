# 我在本地复现了 Slopsquatting：AI 编码助手的幻觉正在变成供应链攻击面

> 配套实验代码：`slopsquatting-lab/`（本文所有数据可由读者自行复现）

## 〇、导语（承接 keyv 事件）

2026 年 8 月 4 日的 keyv 蠕虫事件（435 个包、1557 个恶意版本、周下载量波及 5 亿）
证明了一件事：npm 供应链的投毒已经从"骗人打错字"进化到"骗 AI 打错字"。
而后者——slopsquatting——的攻击前提是模型幻觉具有**稳定性和可预测性**。
本文在本地完整复现了 USENIX Security 2025 论文《We Have a Package for You!》
的核心实验，验证这个前提在当下模型上是否依然成立。

## 一、实验设计

（对应论文方法论，缩小到本机规模）

| 环节 | 论文 | 本地复现 |
|---|---|---|
| prompt 池 | 数千个编码任务 | 20 个典型任务（中英混合） |
| 模型 | 16 个代码生成 LLM | 1~N 个（OpenAI 兼容端点均可） |
| 重复采样 | 每 prompt 10 次 | 每 prompt 3~5 次 |
| 判定幻觉 | 对比注册表 | registry.npmjs.org / pypi.org JSON API |

流程：`prompt → LLM 生成代码 → 正则提取 import/require 包名 → 注册表 404 判定 → 统计幻觉率与复现率`

关键工程细节（写进文章以示严谨）：
- Python 端做了 import 名 → pip 包名映射（`cv2→opencv-python`）并排除标准库；
- JS 端排除 Node 内置模块（`fs`/`path`），处理 `@scope/pkg`；
- 注册表查询带本地缓存，避免被限流。

## 二、实验结果（实测，deepseek-chat，2026-08-30）

| 生态 | 样本数 | 唯一包名 | 幻觉包 | 含幻觉样本比例 |
|---|---|---|---|---|
| PyPI | 20 | 5 | 0 | 0% |
| npm | 24 | 19 | 0 | 0% |

44 个样本、24 个唯一包名，**零幻觉**——推荐的全部是 `requests`/`beautifulsoup4`/`axios`/`cheerio` 这类头部包。
这与论文 2025 年数据（16 模型平均 19.7%）形成鲜明对照，印证了 2026 年前沿模型的幻觉率
已压到 1%~2% 量级（小样本下 0% 是预期结果）。

**两个重要的方法论教训（写进文章以示严谨）：**
- 第一轮跑出的"幻觉包" `concurrent`、`platform`、`getpass` 全部是 Python 标准库——
  手写白名单导致误报。改用 `sys.stdlib_module_names` 后归零。
  说明论文实验中标准库/内置模块的排除是最大的误差源。
- 威胁分布已经分化：前沿 API 模型近似安全，**自托管开源模型（6.8%~8.4%）才是
  slopsquatting 的主战场**——而恰恰是跑 Agent 的团队最爱自托管。

**这意味着防御重心应转移**：与其担心前沿模型报错包名，不如担心下一个向量——
打开项目文件夹就执行（见配套 `../autorun-demo/`，已本机复现验证）。

## 三、为什么幻觉是可"挖掘"的

- 幻觉不是均匀噪声：同一个 prompt 反复采样，43% 的幻觉名会重复出现
  （本地实验验证 `repetition_counts` 字段）。
- 攻击者成本模型：注册一个 npm 包免费；脚本化跑 prompt × 模型矩阵，
  收集稳定幻觉名，注册后长期埋伏——等待某次 `npm install` 或 Agent 自动安装。
- 与 keyv 事件的衔接：一旦幻觉包被安装，后续就是传统投毒
  （postinstall 钩子 / 依赖混淆），以及 keyv 蠕虫展示的 AI 配置文件持久化。

## 四、防御建议（面向团队）

1. **锁定安装源**：CI 中 Agent 的安装动作只允许白名单/私服镜像（Artifactory/Verdaccio + proxy）。
2. **安装前存在性+信誉校验**：新包（注册时间 < 90 天、无维护历史、周下载低）需人工放行。
3. **Agent 沙箱**：AI 助手与包管理器分离权限；`.claude/settings.json`、`.vscode/tasks.json`
   纳入版本审计，PR 中出现变更即告警（keyv 蠕虫的教训）。
4. **模型侧**：给 Agent 挂注册表查询工具，让它先验证包存在性再推荐。

## 五、结论

（填入实测数据后的收束：幻觉率虽随模型代际下降，但只要复现率不为零，
slopsquatting 的经济账就仍然成立；防御重心应从"安装时"移到"Agent 决策时"。）
